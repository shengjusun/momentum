## 一、本轮改动（en_US 共新增 120 条）

1. **第一批 115 条**：代码用 `$r('app.string.xxx')` 之类引用、但 en_US 缺失的 key
2. **第二批 5 条**：⚠️ 上一轮漏判——代码通过 `DeepSeekService.getString('xxx')` 封装取值，不在最初扫描模式内：
   - `ai_default_step` → "Please add the steps manually"
   - `ai_default_task_prefix` → "Task"（拼默认任务名，如 "Task1"）
   - `ai_error_continue` → "AI could not continue. Please retry or rephrase your request."
   - `ai_error_empty_desc` → "Goal description cannot be empty"
   - `ai_error_unparseable` → "Unable to parse the AI response. Please shorten your goal description and retry (the content may have been truncated)."

改动方式：仅向数组末尾追加条目，未重写已有行；随后校验 JSON 合法、name 唯一。

## 三、260 条"死 key"（可选清理）

`base` 里有 259 个 key **无任何源码引用**，是历次重构的遗留（例：`home_empty_title/subtitle` 已被 `home_empty_message/cta` 取代；`ai_error_network/parse/generic` 等 8 条错误文案已被 `DeepSeekService` 的硬编码常量取代；`page_home/page_route/retry/btn_login/mine_*` 等旧页面文案）。

- 注：`ai_error_service_unavailable` 这条"死 key"已在本次修复中被启用（替换 `DeepSeekService` 的硬编码常量）。

## 五、应用内语言切换：已实现（方案 C）

- 新增 key：`settings_language`、`settings_language_default`、`settings_language_zh`、`settings_language_en`、`settings_language_restart_toast`、`settings_language_restart_title/message/now/later`
