# 智感握姿 · 权限与接入说明

> 结论：**`ohos.permission.DETECT_GESTURE` 无需申请，按普通权限声明即可。**
> 本文更正 2026-09-14 的一份错误材料（原《握姿权限申请材料》把它当成受限权限，已作废）。

---

## 一、结论与官方依据

华为官方权限表原文：

```
ohos.permission.DETECT_GESTURE
允许应用感知手势操作。
获取此权限后，应用可感知用户握持姿态、操作手等相关信息。
权限级别：normal
授权方式：系统授权（system_grant）
支持设备：General
起始版本：20
```

它出现在华为文档 **「Open system_grant Permissions」（对所有应用开放的 system_grant 权限）** 列表中。

**system_grant 的含义**：安装即授予，**不弹窗、不需要用户授权、更不需要 AGC 申请**。

所以正确做法只有一条：**在 `module.json5` 里声明即可**（项目已声明，无需任何改动）。用户实测功能可用，即是对这一结论的直接验证。

---

## 二、哪些权限才需要 AGC 申请

**受限开放权限（restricted）** 才需要：先在 AGC 申请**发布 Profile 时勾选**（或邮件 `agconnect@huawei.com` 申请白名单，审核约 1 个工作日），未申请到权限证书却在配置中声明会导致**安装失败**。

典型需要申请的能力（对照）：

| 能力 | 是否需要 AGC 申请 |
|---|---|
| **实况窗**（Live View） | ✅ 需要（受限能力） |
| 代理提醒 `PUBLISH_AGENT_REMINDER`（本项目已声明） | ✅ 需要（走 AGC 开放能力管理申请权益） |
| **智感握姿 `DETECT_GESTURE`** | ❌ **不需要**（normal / system_grant） |

> **判断方法（别再猜）**：查到具体权限后，**先看该权限的「权限级别」与「授权方式」两个字段**。
> `normal / system_grant` → 声明即可；只有明确标为「受限开放权限」的才要走申请流程。
> 不要拿"受限权限申请流程"的**通用说明**去套某个具体权限 —— 这正是本次误判的原因。

## 三、当前实现（无需改动）

`common/services/GripAwarenessService.ets`：

- 通过 `@kit.MultimodalAwarenessKit` 的 `motion.on('holdingHandChanged')` 订阅握持手状态
- `1` = 左手 / `2` = 右手 → 驱动「路线」页 FAB 悬浮按钮左右自适应；`0`（未握持）/ `3`（双手）→ 不处理
- 500ms 防抖，避免握姿抖动导致按钮来回横跳
- **降级策略**：设备不支持（错误码 801）或权限不可用 → 回调 `'unknown'` → UI 保持固定右下角，功能不受影响
- `RoutePage` 在 `aboutToAppear` 订阅、`aboutToDisappear` 退订

**用法与华为官方博客《智感握姿——动作感知实现流程操作指南》列出的典型场景第一条（"FAB 悬浮按钮跟随握持手左右换边"）完全一致。**

## 四、剩余的一项可选优化（非审核硬要求）

华为官方《智感握姿接入原则》提出：**「提供开关选项：允许用户自由关闭此功能，尊重用户选择」**（同时建议"仅为必要组件接入""保持交互一致""统一使用『智感握姿』这一官方术语"）。

当前项目**没有**该开关 —— 用户无法主动关闭。

**建议补**（一次小改动）：
- 设置页新增一行「智感握姿」（默认开启），用 `StorageManager` 持久化
- 关闭 → 不订阅（或立即 `unsubscribe()`），FAB 回退固定右下角
- 设备不支持（801）→ 开关置灰并提示"当前设备不支持"

> 性质说明：这是**产品体验建议**，不是上架审核的硬性要求，可按排期做。

---

## 五、对隐私托管页的影响

由于本权限**不需要申请**，`module.json5` 中的权限声明保持不变即可；隐私托管页的权限表仍需与包内**完全一致**（当前包内 4 项：`INTERNET`、`PUBLISH_AGENT_REMINDER`、`VIBRATE`、`DETECT_GESTURE`），这条与握姿权限本身无关。
