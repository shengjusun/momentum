## 二、申请原因 / 场景说明（可直接复制到申请表单）

```
【场景类型】计时（TIMER）

【业务场景说明】
本应用「起势」是一款个人效率工具，内置番茄钟专注计时功能。用户选定时长（默认 25 分钟专注 + 5 分钟休息，
可选 15/25/35/45 分钟）后，主动点击「开始专注」进入计时。番茄钟的使用常态是：用户开始计时后会把应用切到
后台或直接锁屏，专心投入当前任务、不再看手机。因此需要通过实况窗，把「当前阶段 + 剩余时间」外显到状态栏
胶囊和锁屏界面，让用户不打开应用也能一眼确认进度，避免为了看一眼剩余时间而反复点亮屏幕、打断专注。

【触发时机与生命周期】
1. 触发：仅由用户在应用内主动点击「开始专注」触发（每轮计时生命周期内仅创建一次，绝无自动、批量或静默创建）；
2. 更新方式：端侧本地更新（TIMER 场景仅支持端侧），不依赖 Push Kit 与服务端；
3. 阶段切换：专注结束自动进入休息阶段时，更新为休息阶段文案；休息结束回到专注时同理；
4. 结束：计时完成、用户点击「停止」、或用户退出番茄钟界面时立即结束实况窗；
5. 单次时长：默认 25 分钟，用户最长可选 45 分钟；含休息的完整周期不超过 2 小时，远低于 8 小时上限。

【实况窗展示内容】
1. 状态栏胶囊：当前阶段 + 剩余时间（分钟级，例如「专注中 · 剩余 18 分钟」）；
2. 通知中心 / 锁屏卡片：进度条（已用时间占比）+ 阶段名称 + 剩余时间 + 当前关联任务名称（如用户从某个任务进入计时）；
3. 所有内容仅与本应用的计时状态有关，不含任何其他信息。

【更新频率】
文案为分钟级，采用低频更新（约每 15~60 秒一次），严格遵守实况窗更新频率限制，不做高频滥用。

【为什么需要这个能力】
番茄钟这一场景的核心体验是「用户专注期间不看手机」。若没有实况窗，用户必须点亮屏幕、打开应用才能确认
剩余时间，恰好违背了该功能「减少打断、保持专注」的设计目的。实况窗让进度信息在状态栏与锁屏直接可见，
是该场景的标准交互方式。

【合规承诺】
1. 实况窗仅用于本应用的番茄钟计时场景，绝不用于营销、广告、推广或任何引流内容；
2. 仅在用户主动开始计时后创建，绝不自动创建、后台静默创建或批量创建；
3. 用户停止计时或退出应用后立即结束实况窗，不做常驻展示；
4. 不通过实况窗推送任何消息或额外信息；
5. 严格遵守系统的更新频率与时效性约束（超时未更新会被系统隐藏/清除，我方将确保更新频率充分）。
```

## 三、这个能力落地后代码怎么做（先给结论，等权益下来再动手）

**场景类型对上了**：官方支持场景表里就有 **`TIMER` —— "番茄时钟、倒计时（仅端侧）"**，与我们的业务完全一致，且**不需要服务端推送**，实现成本低。

**接线点（项目已具备，改动很小）**：
- 现有 `PomodoroService` 已有完整的状态机（`startFocus` / `startBreak` / `pause` / `resume` / `stop` / `complete`）与时间 tick 回调 → 实况窗只需挂在这些**已有事件**上：
  - `startFocus` / `startBreak` / `resume` → `startLiveView()` 或 `updateLiveView()`
  - `pause` / `stop` / 计时完成 → `updateLiveView()`（结束态）或 `stopLiveView()`
- 能力探测：调用前先用 `liveViewManager.isLiveViewEnabled()` 判断；返回 false（未登录华为账号 / 用户关闭了实况窗开关 / 权益未开通）→ **静默降级**，不影响番茄钟本体
- 失败兜底：捕获 `67108900`（权益未开通）等错误码，**只落日志**，绝不让实况窗失败影响计时
- 更新策略：文案取**分钟级**（"剩余 18 分钟"），低频更新；避免每秒更新（既不必要，也容易触发系统限流）

**展示形态**：
- 胶囊（后台时出现在状态栏）：阶段 + 剩余分钟
- 卡片（下拉通知中心 / 锁屏）：进度条 + 阶段 + 剩余 + 关联任务名

## 四、注意事项

1. **必须重新生成 Profile**：实况窗权益通过后，要重新生成并替换 Profile 文件再打包，否则权益不生效。
   👉 **可与此前通过的「代理提醒」权益、以及发布签名一起，一次性重新生成 Profile**（同一件事，别分三次做）。
2. **未开通时不要硬调**：未开通权益调用 `startLiveView` 会返回 `67108900` 并且上架后功能失效 —— 代码里要先探测、后调用，失败静默降级。
3. **TIMER 场景仅端侧**：不需要 Push Kit，也不必上报 pushToken；但应用进程被系统回收后更新会中断（番茄钟场景影响很小，因为计时本身就是短时前台/后台活动）。
4. **时效性约束**：超过 2 小时未更新会被隐藏、超过 4 小时会被清除，单条实况窗最长 8 小时 —— 我们的单轮计时远低于这些阈值。
5. **审核意见是硬约束**：与代理提醒一样，权益被发现有超范围使用会**直接禁用**，因此申请文案里承诺的"只用于番茄钟"必须在代码里同样做到。
