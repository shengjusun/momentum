# 编译 → 装机 → 截图：HarmonyOS 无人工验证闭环

> 目的：不打开 DevEco Studio，就能完成「改代码 → 编译 → 装真机 → 操作 UI → 截图亲眼看结果」的完整循环。
> 全部步骤在 Windows + Git Bash 环境实测通过（2026-10-10，HarmonyOS 6.1 / API 23 工程）。

---

## 0. 这套闭环解决什么问题

静态检查（括号平衡 / 资源引用 / 命名规范）**抓不到**三类问题：

1. **ArkTS 类型错与命名撞名**（如 `@Param size` 撞了通用属性方法，编译错 10505001）
2. **视觉与渲染时序**（进度环不刷新、渐变是否发灰、0.5px 分割线在 2x/3x 屏的观感）
3. **真机交互行为**（下滑收起、点击热区、回弹方向）

⇒ **编译是"能不能跑"的唯一权威判据；真机截图是"好不好看/对不对"的唯一权威判据。**

---

## 1. 前提：DevEco Studio 自带 hvigor，工程里**不需要** hvigorw

DevEco 安装目录里有一整套 node + hvigor，直接用它们：

| 组件 | 路径（按本机安装位置替换） |
|---|---|
| node | `D:/harmony/deveco6.1/DevEco Studio/tools/node/node.exe` |
| hvigorw | `D:/harmony/deveco6.1/DevEco Studio/tools/hvigor/bin/hvigorw.js` |
| hdc | `D:/harmony/deveco6.1/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe` |
| SDK | `D:/harmony/deveco6.1/DevEco Studio/sdk` |

先确认 hvigor 可用（应输出版本号，如 `6.26.4`）：

```bash
"D:/harmony/deveco6.1/DevEco Studio/tools/node/node.exe" \
  "D:/harmony/deveco6.1/DevEco Studio/tools/hvigor/bin/hvigorw.js" --version
```

## 2. 第一步：命令行编译

```bash
export DEVECO_SDK_HOME="D:/harmony/deveco6.1/DevEco Studio/sdk"
"D:/harmony/deveco6.1/DevEco Studio/tools/node/node.exe" \
  "D:/harmony/deveco6.1/DevEco Studio/tools/hvigor/bin/hvigorw.js" \
  assembleHap --mode module -p product=default -p module=entry@default --no-daemon
```

要点：

- **`DEVECO_SDK_HOME` 必须设**，否则 hvigor 找不到 SDK。
- `--no-daemon`：不留常驻构建进程（脚本场景必备）。
- **只验编译、不打包签名**：把任务名换成 `default@CompileArkTS`，更快（增量约 3~12s）。
- **日志必须重定向到文件再读**：某些终端环境下 hvigor 的 stdout 会丢/乱，
  `> build.log 2>&1` 后再 `grep`，这是实测踩过的坑。
- 产物：`entry/build/default/outputs/default/entry-default-signed.hap`（debug 签名，可直接装机）。
- 判定成功：日志末尾 `BUILD SUCCESSFUL`；`grep -cE "ArkTS Compiler Error" build.log` 应为 `0`。
- 无关警告（非错，勿慌）：各 `@Entry` 页面 "not a recommended way to export struct"、
  三方库的 `sourceMapsPath` 提示。

---

## 3. 第二步：装到真机（无线即可）

```bash
export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"   # ⚠️ 见第 6 节坑 1
HDC="D:/harmony/deveco6.1/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"

"$HDC" list targets                                   # 确认设备在线（如 192.168.1.101:41687）
"$HDC" install -r entry/build/default/outputs/default/entry-default-signed.hap
"$HDC" shell aa start -a EntryAbility -b com.example.yourapp
```

要点：

- **`install -r` = 覆盖安装并保留应用数据**（本地数据不丢；有云同步的还有一层兜底）。
  若签名不一致会直接报错、不会装上——这也算一种保护。
- `-b` 后面换成你工程的 bundleName（`AppScope/app.json5` 里的 `bundleName`）。
- 无线连接：真机与电脑同一局域网，DevEco 里配一次后 `hdc list targets` 就能看到 `ip:port`。

---

## 4. 第三步：操作 UI（`uitest`，模拟人的点击/滑动）

```bash
"$HDC" shell uitest uiInput click 480 2684                        # 单击
"$HDC" shell uitest uiInput swipe 600 2100 600 1200 400           # 滑动（起点→终点，毫秒）
```

要点：

- **坐标系 = 设备物理像素**，不是 vp。先截一张图看分辨率（如 1272×2860），
  再按截图里的比例换算坐标。
- 常用套路：**点一下 → sleep 2~3 秒 → 截图 → 看图 → 再决定点哪**，像人一样逐步导航。
- `click` 对 `List`/`Scroll` 区域按下再拖动即可滚动（用 `swipe`）。

---

## 5. 第四步：截图回传 + 亲眼验证

```bash
"$HDC" shell snapshot_display -f /data/local/tmp/s1.jpeg
"$HDC" file recv /data/local/tmp/s1.jpeg .workbuddy/s1.jpeg
```

然后用支持看图的工具（或 AI 的 Read）打开 `s1.jpeg` **亲眼看**：布局、颜色、间距、
圆角、遮挡关系，一眼即判——这比任何静态检查都可靠。

要点：

- `snapshot_display` 的 `-f` 路径是**设备侧**路径。
- `file recv` 的第二个参数建议用**相对路径**（见第 6 节坑 2/坑 3）。

---

## 6. 必须绕开的坑清单（每条都实测踩过）

### 坑 1：Git Bash 会把 `/data/...` 转成 Windows 路径
现象：`hdc shell snapshot_display -f /data/local/tmp/s.jpg` 报
`error: fileName D:/software/.../data/local/tmp/s.jpg invalid`。
**解法**：命令前加 `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"`。

### 坑 2：`hdc file recv` 的本地路径被拼上 cwd
现象：关掉路径转换后，`recv ... D:/proj/x.jpg` 变成 `D:/proj/D:/proj/x.jpg`。
**解法**：本地目标用**相对路径**（`.workbuddy/s1.jpeg`），hdc 会以当前目录解析。

### 坑 3：含反引号的内容**禁止**走 `bash -c` / `python -c`
现象：命令里注释含 `` `task.steps = steps` ``，反引号被 shell 当命令替换执行，
日志里出现 `task.steps: command not found`，**写入文件的注释被吃掉半句**。
**解法**：要写入含反引号的代码/注释，一律用编辑器/文件写入工具，不走 shell 内联。

### 坑 4：`onDidScroll` 回调参数是**每帧增量**，不是绝对位置
做"滚动联动 UI"（如标题栏渐变、FAB 下滑收起）时：
- 绝对位置用 `Scroller.currentOffset().yOffset`；
- 但 SDK **没有写明符号约定**，按"下滑为负"实现可能完全不触发 ⇒
  **改用不依赖符号的信号**（如 `List.onScrollIndex` 的首个可见项下标增减）。

### 坑 5：静态护栏全绿 ≠ 能跑
护栏只覆盖文本层。**改完代码必须编译一次再交付**；改 UI 必须装机截图。

## 7. 一键脚本（复制即用，改 4 个路径变量即可）

```bash
#!/usr/bin/env bash
# verify.sh —— 编译 → 装机 → 启动 → 截图
set -e
DEVECO="D:/harmony/deveco6.1/DevEco Studio"
NODE="$DEVECO/tools/node/node.exe"
HVIGOR="$DEVECO/tools/hvigor/bin/hvigorw.js"
HDC="$DEVECO/sdk/default/openharmony/toolchains/hdc.exe"
BUNDLE="com.example.yourapp"                     # ← 改成你的 bundleName
OUT="entry/build/default/outputs/default/entry-default-signed.hap"

export DEVECO_SDK_HOME="$DEVECO/sdk"
export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"

echo "== 1. 编译 =="
"$NODE" "$HVIGOR" assembleHap --mode module -p product=default \
  -p module=entry@default --no-daemon > .verify-build.log 2>&1 \
  || { tail -30 .verify-build.log; exit 1; }
grep -cE "ArkTS Compiler Error" .verify-build.log | grep -q '^0$' \
  || { echo "存在编译错误："; grep -A5 "ArkTS Compiler Error" .verify-build.log | head -40; exit 1; }
echo "编译 OK"

echo "== 2. 装机 =="
"$HDC" install -r "$OUT"

echo "== 3. 启动 =="
"$HDC" shell aa start -a EntryAbility -b "$BUNDLE"
sleep 4

echo "== 4. 截图 =="
"$HDC" shell snapshot_display -f /data/local/tmp/verify.jpeg
"$HDC" file recv /data/local/tmp/verify.jpeg .verify-shot.jpeg
echo "截图已保存：.verify-shot.jpeg —— 打开它亲眼确认"
```

## 8. 在另一个项目落地的检查清单

1. hvigorw / node / hdc / SDK 四个路径换成新机器的 DevEco 安装位置。
2. `bundleName`、模块名（`entry@default`）、产物路径按新工程改。
3. 真机 `hdc list targets` 能看到设备（无线需同局域网）。
4. 第一次跑先 `--version` 探测 hvigor，再全量编译一次（约 30s，之后增量 3~12s）。
5. 把第 6 节的坑清单贴在手边——它们都是环境层的，与具体工程无关。
6. 建立"改完 → 编译 → 装机 → 截图"的固定节奏，**不要**用"我觉得应该没问题"代替。
