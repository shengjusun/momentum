# 应用接续（跨端迁移）权限结论 —— DISTRIBUTED_DATASYNC 是否必须

> 结论：**Momentum 的接续方案不需要声明 `ohos.permission.DISTRIBUTED_DATASYNC`。**
> 权限是否需要，取决于迁移过程中**是否使用了分布式数据同步能力**，而不是「是否做了跨端迁移」。适用 API 24（HarmonyOS 6.1）。

## 判定规则

| 迁移数据方式 | 是否需要 DISTRIBUTED_DATASYNC |
|---|---|
| 仅用 wantParam 传简单数据（< 100KB） | **不需要**，配置 `continuable: true` + 实现 `onContinue`/`onCreate`/`onNewWant` 即可 |
| 分布式数据对象 `distributedDataObject` | 需要（声明 + 运行时动态申请） |
| 分布式文件系统 | 需要 |
| 分布式数据库（`relationalStore` / `distributedKVStore`）跨设备同步 | 需要 |
| 分布式设备管理 `deviceManager` 发现设备 | 需要 |

## 本项目核对结果（2026-09-11）

**代码证据 —— 走的正是「仅 wantParam」路径：**

- `EntryAbility.onContinue()`：仅写 `wantParam`，字段为 `routeName` / `param` / `tabIndex`，另附 `migrationData`（UTF-8 的 JSON `ArrayBuffer`），无分布式数据对象、无文件传输
- `onNewWant()` → `extractMigrationData()`：从 `want.parameters.migrationData` 解析回路由参数，走本地 `globalNavStack` 还原
- 全工程检索 `distributedDataObject` / `deviceManager` / `distributedKVStore` / `relationalStore` / `@kit.DistributedDataKit` / `distributedFile`：**零命中**
- 跨端数据一致性由自家 AGC CloudDB 同步（`CloudSyncService.smartSync`）承担，与分布式数据同步权限无关
- 载荷为路由名 + 页面参数（多为 id 类短字符串）+ tabIndex，远低于 100KB 上限

**配置现状：**

- `module.json5`：`continuable: true`（`EntryAbility`），**无** `DISTRIBUTED_DATASYNC` 声明 —— 与上述判定一致，正确
- `EntryAbility`：已移除 `abilityAccessCtrl/Permissions` 导入与动态申请方法，无残留
- `resources`：已无 `reason_distributed_sync` 等悬空字符串引用

## 仍需注意的两点

1. **载荷体积要守住 100KB 红线**。当前只传路由参数没问题；若将来把目标列表/画像等大数据塞进 `param`，就会超出限制。传大数据的正确做法是接续后由 CloudDB 同步拉取，而不是塞进 `wantParam`。建议在 `onContinue` 里加一行长度校验与告警日志。
2. **不要反向改动**。若后续因误判又把该权限声明加回，反而可能在审核时被质疑「声明了 permission 但未实际使用分布式数据同步能力」。保持现状即可。
