# 本文件已按官方文档要求（source-obfuscation-rule-options / source-obfuscation-questions）
# 配置好 keep 白名单。官方明确：使用数据库字段、JSON 字段时，
# 必须用 -keep-property-name 保留名称，否则混淆后 JSON 键与数据不一致。
#
# 本应用三类"名称即数据"的高危场景（改动数据结构时必须同步维护下方白名单）：
#   1. CloudDB 字段（UserSyncData / UserFeedback）：字段名被改 = 云同步【静默失败】
#      —— 不报错、数据传不上去，最难排查。参考 2026-09-13 复核报告 P0。
#   2. 本地持久化快照的 JSON key（StorageManager 全部存储）：键被改 =
#      老用户升级后本地数据读不回来（等于丢数据）。
#   3. 网络 JSON 字段（DeepSeek 响应）：访问点被改 = AI 功能直接失效。
#
# 已知安全边界（2026-09-13 依据官方文档确认）：
#   - 字符串字面量属性名不会被混淆（如 data['goals']）→ 方括号字符串访问天然安全
#   - ArkUI 组件属性名、SDK API 名称由系统白名单自动保留
#   - -enable-string-property-obfuscation 未开启 → 字符串 key 双保险
#
# 启用混淆（build-profile.json5 的 enable: true）后必须做的验证：
#   ① release 包真机：老本地数据能正常读出（验证第 2 类）
#   ② 登录 + 云同步上传下载各一次，控制台核对字段（验证第 1 类）
#   ③ AI 拆解跑一次（验证第 3 类）
#   ④ 可用 DevEco「混淆助手」交叉检查遗漏的保留项
# ============================================================
